PHASE 1: THE HACKER MINDSET

🧠 Thinking Like a Hacker

Before any tool is launched, a hacker develops a mental model of the target. They think about:

• Trust boundaries — Where does the system trust input?

• Attack surface — What can be reached from the outside?

• Assumptions — What does the system assume is true that might be false?

• Chain of trust — What happens if one component is compromised?

mindset — scenario-01.txt
scenario@mindset:~$ load scenario --id=web-app-auth
[SCENARIO] You're analyzing a web application's login page.
[OBSERVATION] The login form has username/password fields.
[OBSERVATION] After 5 failed attempts, you get a "lockout" message.
[OBSERVATION] The error message says: "Username not found" vs "Invalid password"
[QUESTION] What vulnerability does this reveal?

Q1: The different error messages for "user not found" vs "wrong password" allow an attacker to:

✅ Correct! User Enumeration

Different error messages reveal whether a username exists in the system. An attacker can iterate through common usernames, then focus brute-force attacks on confirmed accounts. This is why systems should return generic error messages like "Invalid username or password."

mindset — scenario-02.txt
scenario@mindset:~$ load scenario --id=developer-assumption
[SCENARIO] A developer wrote this validation rule:

[QUESTION] What's the fundamental flaw in this approach?

Q2: This code assumes that:

✅ Correct! Trust Boundary Violation

This is a classic client-side trustNever trust data from the client. If role checking happens in JavaScript on the user's browser, an attacker can modify the role field in browser dev tools before sending the request. problem. If role validation happens on the client (browser), an attacker can modify the role in browser developer tools. Server-side validation is essential — never trust user input.

[OBSERVATION] and use the default password "admin123"

Q3: Hiding the admin URL instead of securing it violates:

✅ Correct! Security by Obscurity

Kerckhoffs's principleNamed after cryptographer Auguste Kerckhoffs: a system should remain secure even if everything about the system, except the key, is public knowledge. Hiding the URL is not security — it's just making it harder to find. states that a system should remain secure even if everything about it is known except the key. Hiding an admin URL provides no real protection — anyone who discovers the URL has full access. Real security requires authentication, authorization, and encryption.

🧠 Mindset Summary

The hacker's mindset is built on three pillars:

1. Curiosity — Question every assumption the system makes

2. Persistence — If one path is blocked, find another

3. Systematic thinking — Map the attack surface before acting

Now that you think like a hacker, it's time to gather intelligence.

PHASE 2: RECONNAISSANCE

🔍 Gathering Intelligence

Reconnaissance is the most critical phase. A hacker collects information about the target to identify potential entry points. This includes:

• Network mapping — Finding live hosts and open ports

• Service enumeration — What's running on each port?

• Technology fingerprinting — What software and versions?

• OSINT — Open Source Intelligence from public sources

recon — network-scan.sh
recon@target:~$ nmap -sV --script=vuln 10.0.0.0/24
[SCANNING] Network 10.0.0.0/24 — 256 hosts
[ALERT] 8 hosts found with open ports.
[INSTRUCTION] Click on each node to scan it. Identify vulnerabilities.
💡 Hint: Focus on nodes with open ports. Each node reveals different services. Look for outdated software versions and misconfigurations. You need to find at least 3 vulnerabilities to proceed.

📚 Key Takeaways

• Think first, act second. Understanding the system is more important than any tool.

• Recon is 80% of the work. The better you know your target, the easier the exploit.

• Chain vulnerabilities. Single vulnerabilities are often mitigated; chains bypass defenses.

• Defense in depth. Layer your security — no single point of failure.

• Never trust input. Validate everything, sanitize everything, authenticate everything.
